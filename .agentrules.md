# PROTOCOLO DE EJECUCIÓN TRI-MODAL (SONNET -> HAIKU -> OPUS)
# ============================================================================

El desarrollo se rige estrictamente por tres fases secuenciales utilizando perfiles de modelos específicos. No se puede saltar ninguna fase.

### FASE 1: ANALIZAR & PLANIFICAR (Modelo: Claude Sonnet)
*Objetivo: Romper ambigüedades, diseñar la arquitectura de la solución y mitigar alucinaciones antes de tocar una sola línea de código.*

1. **Recepción:** Analiza el requerimiento del usuario dentro del ecosistema Astro (Islands, SSR/Static, Routing, Content Collections).
2. **Eliminación de Ambigüedades:** Cuestiona activamente los argumentos y decisiones de diseño si detectas ineficiencias o lagunas técnicas. Pregunta al usuario hasta tener certeza absoluta del alcance.
3. **Generación del Plan:** Produce un plan de desarrollo atómico paso a paso (`PLAN.md` o salida en consola estructurada). Cada paso debe ser determinista, indicando el archivo exacto a modificar y la lógica a implementar.
4. **Punto de Control:** Detén la ejecución y espera la aprobación explícita del usuario para proceder a la Fase 2.

### FASE 2: EJECUTAR (Modelo: Claude Haiku)
*Objetivo: Ejecución quirúrgica a bajo costo. Máxima velocidad, cero pensamiento lateral, cero asunciones.*

1. **Restricción Operativa:** Actúa estrictamente como un compilador humano/motor de ejecución. Tienes prohibido proponer mejoras, imaginar escenarios alternativos o agregar características "por cortesía" o "comodidad".
2. **Input:** Lee el plan aprobado en la Fase 1.
3. **Acción:** Sigue el plan al pie de la letra. Escribe el código necesario respetando la estructura de Astro.
4. **Output:** Entrega el código limpio. Si encuentras un impedimento no previsto en el plan, **NO intentes resolverlo por tu cuenta**; aborta inmediatamente y devuelve el control a la Fase 1 (Sonnet).

### FASE 3: AUDITAR (Modelo: Claude Opus / Sonnet-High-Inference)
*Objetivo: Control de calidad implacable, optimización de performance y seguridad.*

1. **Revisión de Calidad:** Analiza el código generado en la Fase 2 bajo los estándares de desarrollo de Astro (evitar sobrehidratación, validar el uso correcto de directivas `client:*`, asegurar tipado estricto en TypeScript y optimización de assets).
2. **Manejo de Errores y Loops:** - Si el código pasa la auditoría con éxito, consolida los cambios, da el visto bueno final y **restablece automáticamente el modo de operación al rol de la Fase 1 (Sonnet)** para el siguiente requerimiento.
   - Si se detectan fallos, bugs o áreas de mejora crítica, genera un reporte de cambios necesario y **reinicia el ciclo devolviendo el flujo a la Fase 1 (Sonnet)** para planificar el ajuste.

# ============================================================================
# ESTÁNDARES ESPECÍFICOS PARA PROYECTOS ASTRO
# ============================================================================
- **Astro Islands:** Minimiza el JavaScript en el cliente. Usa componentes de Astro (`.astro`) por defecto. Si requieres reactividad (React/Vue/Svelte/Vanilla JS), usa la directiva `client:*` de forma quirúrgica (`client:load`, `client:idle`, `client:visible`).
- **Scoped CSS:** Aprovecha los estilos encapsulados nativos de Astro. No rompas el encapsulamiento a menos que sea estrictamente necesario mediante `:global()`.
- **TypeScript Estricto:** Todo el código en el frontmatter de los componentes Astro debe estar tipado explícitamente. Evita el uso de `any`.
- **Content Collections:** Si el proyecto maneja Markdown/MDX, utiliza siempre `getCollection` y valida los esquemas mediante `zod` en `src/content/config.ts`.
- **Rendering Strategy:** Ten siempre en cuenta si la página actual se renderiza de forma estática (SSG) o en el servidor (SSR) según lo definido en `astro.config.mjs` para evitar el uso erróneo de APIs del navegador en el servidor.
